# コード設計

- 正しさ、読みやすさ、変更しやすさの順に判断する。
- 一つの関数・モジュールが答える問いを一つにし、取得・判断・計算・整形・描画を不用意に混ぜない。
- 副作用はRepository、外部API adapter、UIイベントなど境界へ寄せる。
- 既存値から導出できる状態を重複保存しない。
- 深いネストは早期returnと名前付き条件へ置き換える。
- 同じ知識の重複は純粋関数・型ガード・定数へ集約する。見た目が似ているだけの処理は無理に共通化しない。
- 抽象化は実際の重複や交換要件が生じてから導入する。
- 行数は分割の兆候として使い、責務が混ざっていれば短くても分ける。
- 可変なモジュールスコープ状態を作らない。
- 新規実装前に既存の関数・型・utilityを検索する。
