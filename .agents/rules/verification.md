# 検証

- 変更前に既存のテスト・build・lint・型検査コマンドを確認する。
- 変更範囲に最も近い検証から実行し、最後に対象全体の検証と差分確認を行う。
- 不具合修正では再現条件を確認し、可能なら回帰テストを追加する。
- 新機能では価値の高い境界・失敗経路・主要導線を優先してテストする。
- coverage率だけを目的にせず、プロジェクトが定めた基準があれば従う。
- UI変更は実ブラウザで主要viewport、keyboard操作、overflow、loading・empty・error状態を確認する。
- 本番設定を変更した場合はdry-runまたはpreview環境で構成を検証する。
- 検証不能な項目は成功扱いにせず、未確認理由と再現コマンドを残す。
