# エラー処理とログ

- エラーは「利用者が次の行動を判断できる」「運用者が原因を追える」の両方を満たす形で扱う。
- `catch`後に無言で既定値へ落とさない。想定内のフォールバックだけは理由をコードから読めるようにする。
- 再throw時は操作名などの文脈を加え、可能なら`cause`で元エラーを保持する。
- 保存・認証・整合性など継続不能な失敗と、通知など縮退可能な失敗を区別する。
- 失敗を無視できる場合も、障害調査に必要なら安全なログを残す。
- Promiseを浮かせず、`await`・`return`・ランタイムの追跡APIのいずれかで完了を追う。
- ログへtoken、秘密値、個人情報、入力本文を出さない。
